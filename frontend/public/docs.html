Developer Guide

Learn how to customize, expand, and add new services to the Self Host Tool App Store registry using declarative JSON templates.

📖 Declarative App Store Philosophy

The portal registry is entirely template-driven. Instead of writing custom installation code, you define your application in a single JSON template file. The portal engine reads this file, renders a configurations form, configures reverse-proxy routing rules, and launches the container stack automatically.

🔌 Portal Architecture

The Self Host Portal uses a unified pipeline that orchestrates the lifetime of all applications:

📦 Docker Compose Sandbox

Every application runs in an isolated container. They connect to the shared selfhost-network Docker bridge, maintaining network security.

🛡️ Caddy Reverse Proxy

Caddy routes incoming requests dynamically to your container using service DNS. Port exposures to the host system are completely blocked.

🔑 Zero-Config Tailscale SSL

Tailscale manages VPN connection and dynamic DNS, securing all routes (HTTP/HTTPS) automatically without exposing router ports.

📄 JSON Schema Definition

Each application is defined by a JSON file saved in the backend/templates/ directory. Below is the blueprint of required fields:

Field Name Type Description Required
id string Unique URL-friendly ID for the app (e.g. jellyfin). Yes
name string Human-readable label displayed on application cards. Yes
description string Brief summary outlining what the application does. Yes
category string Store categorization (e.g. Media, Network, Development). Yes
icon string An emoji or CSS icon class representative of the app. Yes
open_path string The URL subpath prefix (e.g. /files/, /jellyfin/). Yes
fields array Custom user inputs collected during setup (e.g. passwords). No
compose_template string Multi-line string block representing the docker-compose.yml file. Yes
caddy_template string Caddy routing blocks directing traffic to the container. Yes

🔄 Variables Injection

The backend portal engine automatically substitutes context variables inside your templates when rendering the container configurations:

⚙️ Built-In Context Variables

  • {{APP_DATA_DIR}}: Absolute path to the app's persistent storage folder (e.g., data/apps/my-app).
  • {{DATA_DIR}}: The main shared data directory path on the host.
  • {{PORTAL_DOMAIN}}: The current VPN domain or IP address (e.g. ubuntu-desktop.tail5cda40.ts.net).

Any parameter you define in the fields array (e.g. PASSWORD) is also injected via brackets (e.g. {{PASSWORD}}).

🎛️ Custom Input Fields

If your application requires custom credentials or setup parameters, define them in the fields array. The dashboard UI will dynamically compile these into a configuration form:

JSON 
"fields": [
  {
    "key": "PASSWORD",
    "label": "VS Code Password",
    "type": "password",
    "placeholder": "secretpassword",
    "required": true,
    "help": "Set the password you will use to log into VS Code."
  }
]

🛠️ How to Add a New App

Follow these simple steps to integrate a new application into the portal:

  1. Design the Template: Create a JSON file named <app-id>.json using the template format.
    Example Template (jellyfin.json) 
    {
  "id": "jellyfin",
  "name": "Jellyfin",
  "description": "Free Software Media System that puts you in control of managing and streaming your media.",
  "category": "Media",
  "icon": "🎬",
  "open_path": "/jellyfin/",
  "fields": [],
  "compose_template": "version: '3.8'\n\nservices:\n  jellyfin:\n    image: jellyfin/jellyfin:latest\n    container_name: selfhost-jellyfin\n    volumes:\n      - {{APP_DATA_DIR}}/config:/config\n      - {{APP_DATA_DIR}}/cache:/cache\n      - {{DATA_DIR}}:/media\n    restart: unless-stopped\n\nnetworks:\n  default:\n    name: selfhost-network\n    external: true\n",
  "caddy_template": "handle /jellyfin* {\n    reverse_proxy selfhost-jellyfin:8096\n}\n"
}
  2. Save the File: Store the file in the backend/templates/ directory.
  3. Test Locally: Refresh the Dashboard, navigate to the App Store, find your card, configure it, and click Deploy Stack.

🧪 Verifying and Publishing

⚠️ Important: State Isolation Rule

Always mount database or configuration directories inside {{APP_DATA_DIR}} on the host system. This ensures that if the user decides to uninstall the app, all configuration logs and container states are removed without leaving orphaned files.

Once you verify that the container starts up and that Caddy proxies paths cleanly, you have two ways to publish or deploy your application template:

🌎 Add App for Everyone (GitHub Pull Request)

To share your app template with the community so any installer user can access it:

  1. Fork the official repository on GitHub: https://github.com/Jackson-Brooks/self-host-tool.
  2. Commit your custom JSON template file inside the backend/templates/ directory of your fork.
  3. Submit a Pull Request (PR) to the main branch of the parent repository.
  4. Once reviewed and merged by the maintainer, it will be automatically fetched for all users on update.

🔒 Add App for Yourself (Local / Private App)

To test the app locally or run private custom applications without submitting them to GitHub:

  1. Connect to your running instance host VM via SSH/SFTP or open the integrated VS Code Server workspace.
  2. Create or upload your custom <app-id>.json file directly into the backend/templates/ directory.
  3. Open your dashboard and refresh the browser. The new application card will instantly load in your App Store catalog.
